# InterWise GOAI 比赛 Demo 指南

## 一句话定位

InterWise 是一个“会根据回答改变下一问”的 AI 面试训练教练：它不是照着题单顺序发问，而是调用岗位知识、简历证据和学习覆盖三个只读工具，决定本轮应当深挖、补救、换题、追问项目或切换阶段，并把训练结果沉淀为可复盘报告。

## 参赛范围

- 赛道：无界应用，AI + 教育。
- 目标用户：需要技术面试训练的学生、求职者和转岗工程师。
- 本地部署题库：用户既可使用公共 starter 题库，也可新增和维护自己的私有岗位 / 题库；`ADMIN` 额外维护公共内容。
- 非目标：在线招聘筛选、自动录用决策、任意 PDF 自动入库、开放式多 Agent 平台。

## 推荐演示闭环

1. 在“大模型配置”中启用一个支持 Tool Calling 的 OpenAI-compatible 模型。
2. 进入“面试准备”，选择内置岗位、难度和重点能力；可选上传该岗位的简历。
3. 开始文字或视频面试，先完成开场，再进入技术面。
4. 对一个问题给出有明显缺口的回答，展示 Agent 选择“补救追问”或“继续深挖”。
5. 再给出一个完整回答，展示 Agent 调用岗位知识或覆盖率后切换主题；如已上传简历，可展示“项目追问”。
6. 指出面试页顶部的决策条：它只显示安全摘要、工具类型和降级原因分类，不暴露题库答案、模型思维链、内部异常或内部 ID。
7. 结束面试，进入历史报告和 AI Mentor，展示逐轮问答、评分、知识覆盖和下一步训练建议。

## 答辩时要讲清的三个点

### 1. 它确实有 Agent 决策

技术阶段每轮先由规划 Agent 选择动作和只读工具，再由面试模型生成下一问。动作会改变实际 Prompt 或阶段，不是给既定流程加一个“Agent”标签。

### 2. 它不是失控的自治系统

用户、岗位和记录作用域由服务端固定；工具只读且每轮优先只调用一个最相关工具；严格 JSON 输出；提前进入 HR 有轮次门槛；首次规划超时只回退当前轮并在下一技术轮自动重试，连续第二次超时或其他 Agent 规划失败后整场会话保持稳定规则。

### 3. 它形成了教育闭环

内置题库提供可审核的考点，Agent 根据回答动态教学，报告和 AI Mentor 再把薄弱点转成后续训练建议。用户看到的是“训练—反馈—再训练”，不是一次聊天。

## 演示前验收

- 普通账号能进入题库维护页并新增自己的私有岗位，但不能修改公共题库或其他账号的私有内容。
- 普通账号仍能看到公共岗位并成功获得结构化 `positionId`。
- 所有管理员拥有一致能力：能维护公共题库、创建自己的私有岗位，但不能修改他人的私有数据。
- 技术面 SSE 能收到 `AGENT`、`RULE` 或 `RULE_FALLBACK` 决策事件，文字和视频页均能正常显示。
- Agent 正常时，工具证据和动作会影响实际下一问；首次规划超时时面试不中断且下一技术轮会重试，连续第二次超时或其他 Agent 规划失败时后续轮次保持规则模式。
- `interview_turn` 能记录模式、动作和脱敏决策元数据，不记录思维链和 Provider 原始错误。
- 面试结束、报告生成、AI Mentor 和历史记录仍可完成。
