# ADR 0002：在岗位题库工作台内提供受控题库构建 Agent

- 状态：已被 [ADR 0003](0003-controlled-question-bank-ingestion-pipeline.md) 部分取代
- 日期：2026-08-06

## 背景

InterWise 当前通过本机 `interview-question-bank` skill 将 PDF、DOCX、TXT、MD 或 JSON 资料转换成标准导入包，再由用户在知识库 / 题库工作台中校验、导入草稿、审查和发布。这个流程保持了题库质量和作用域安全，但要求用户离开主应用运行本机工具，普通用户的使用门槛较高。

项目曾提供应用内源文件转换和原子生成能力，后来为了收紧产品边界而移除。现在用户明确确认重新引入该能力，但要求保留人工审核、草稿导入和显式发布，不恢复任意文档自动入库或自动发布。

## 决策

1. 在现有知识库 / 题库工作台中新增岗位上下文内的四标签工作区：`概览`、`智能构建`、`候选审核`、`题库原子`，不增加独立一级导航。
2. 新增受控的 `QuestionBankBuild` 模块。模块接口只提供：
   - 在当前用户有权维护的知识库中创建文档构建；
   - 查询当前知识库的构建任务与候选；
   - 接受、修改或拒绝候选原子；
   - 下载标准 JSON 导入包；
   - 将已接受候选显式导入为 `DRAFT`；
   - 删除构建及其保留的源文件。
3. PDF、DOCX、TXT、MD 文档在服务端完成类型校验、文本提取和分块。扫描 PDF、加密 PDF、无有效文本或不支持格式必须明确失败，不允许让模型猜测内容。
4. 构建使用当前执行用户启用的 OpenAI-compatible Provider。任务保存配置 ID、Provider、模型和提示词版本快照，但不保存 API Key、原始模型错误或思维链。没有 active Provider 时阻止创建任务。
5. 长文档构建使用 MySQL `app_job` 与本地 `TaskExecutor` 异步执行，支持进度、启动恢复和失败重试；成功分块不得因重试重复调用模型。若极端中断只落库了一个分块的部分候选，则必须 fail-closed 并要求删除批次重建，不能用新一轮可能重排的模型输出拼接旧候选。
6. 模型输出沿用 `QuestionBankImportRequest` / `KnowledgeAtomPayload` 契约，并增加来源证据、模型自检和重复提示。模型自检不能替代人工审核。
7. 候选与题库原子分离。只有人工接受或修改后接受的候选能进入导入包；显式导入后状态为 `DRAFT`，此时不写 Qdrant。
8. 所有发布入口统一要求人工审核通过。发布后才写入 Qdrant；同步失败继续在 MySQL 中保留为可重试状态。
9. 构建工件只对发起人可见和可操作；管理员也不能读取其他用户或其他管理员的私有构建、文件或候选。
10. 公共 starter 题库开放给 `ADMIN` 使用同一受控流水线，但公共题库只作为终审发布目标，构建工件继续保持发起管理员私有。该后续决策由 ADR 0003 取代本 ADR 原有的“公共仅 JSON 导入”限制。
11. 原始文件随构建批次保留在应用数据目录中，用于来源对照和失败恢复；用户删除构建时一并删除。文件不进入 Git，不对其他用户公开。

## 结果

优点：

- 用户可以在一个岗位上下文内完成上传、生成、审核、导入和发布，不再依赖本机命令行。
- 候选、草稿、已发布三个阶段保持清晰，模型不能绕过人工治理。
- 复用现有用户 LLM、异步作业、题库版本和 Qdrant 补偿链路。
- 构建任务、模型快照和来源证据可追踪，失败可以恢复。

代价：

- 主应用重新承担不可信文档解析和持久化，需要文件安全、容量、清理和云端配额治理。
- 每个文档可能产生多次模型调用，用户承担额外 Provider 成本。
- 候选审核和来源对照需要新的持久化模型与较复杂的桌面/移动端交互。

## 暂不采用

- 上传后自动入库或自动发布：会绕过人工审核并污染面试检索。
- 在 Java 容器中调用 Python skill：会引入第二套运行时、密钥和依赖边界。
- 独立题库 Agent 一级导航：当前主要路径仍是维护单个岗位，独立任务中心会割裂岗位上下文。
- 扫描 PDF OCR、旧版 `.doc`、PPT、网页抓取和图片理解：不属于第一版范围。
