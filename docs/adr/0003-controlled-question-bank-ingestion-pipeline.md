# ADR 0003：以受控文档入库流水线替代双自治 Agent

- 状态：已接受
- 日期：2026-08-10

InterWise 不建设两个自由自治、互相对话的题库 Agent。应用内可维护题库采用一条可恢复的文档入库流水线：确定性程序负责文件安全、解析、分块、契约校验、作用域和状态流转；知识原子生成器只依据原文生成候选；质量监督器结合原文、规则结果和目标题库相似原子给出结构化机器结论；私有 owner 或公共题库管理员通过批次终审显式触发发布。

机器质量状态与人工审核状态必须分离。自动通过只表示候选可以进入批次终审，不能冒充人工接受；监督异常先进入最多两轮的“修复助手修改 → 重新监督”，修复仍不确定的候选留在批次内且默认不发布，不阻断同批次其他合格候选终审。自动淘汰项默认不发布。终审先在 MySQL 中形成可审计草稿和发布状态，再通过可重试的索引步骤同步 Qdrant，任何模型节点都没有发布、跨 owner 读取或切换 Provider 的权限。

流水线状态为 `QUEUED → PARSING → CLASSIFYING → GENERATING → SUPERVISING → REPAIRING → RESUPERVISING → READY_FOR_FINAL_REVIEW → FINALIZING → PUBLISHING → INDEXING → PUBLISHED`。解析、分类规划、生成、监督、修复和索引都是可观察的异步阶段；用户手动指定分类目录时可跳过 `CLASSIFYING`，没有异常时可跳过修复阶段。用户可在最终审核页给仍需关注的候选补充一次受限修复要求，但发布仍只能由显式终审触发，不提供能够自行发布的对话 Agent。

## 考虑过的方案

- 两个自治 Agent 互相生成和监督：拒绝。它会增加模型调用、状态恢复和调试复杂度，同一模型还可能重复强化错误。
- 保留现有单模型自检并增加批量接受：拒绝。旧自检没有读取完整原文或同作用域相似原子，且结果不构成正式质量门。
- 上传后自动发布：拒绝。它会绕过人工终审并直接污染面试检索。

## 后果

- 用户的常规操作从逐条机械接受收敛为“查看自动修复结果 + 一次批次终审”；修复耗尽项可继续留存，也可由用户选择再次让助手处理。
- 主应用需要持久化生成调用检查点、已保存模型响应、机器审核结论、终审 revision 和最终原子列表。自动恢复不得重复调用结果不确定的模型请求；用户显式重试才授权再次调用，终审重试不得重复导入草稿。
- 用户不指定分类范围时，流水线先按整批文档规划 2 到 10 个稳定、同层级的知识领域分类，不允许使用“通用”“未分类”或“其他”兜底；用户指定的分类则成为严格目录。生成、修复和人工接受均不能写入目录外分类，岗位覆盖图直接按最终原子的同一分类统计。
- 私有知识库只允许 owner 发起流水线；公共 starter 知识库只允许 `ADMIN` 发起，普通用户只读。
- 公共题库只是发布目标。源文档、构建批次、候选和异步作业始终保持 `PRIVATE + 发起管理员 owner_user_id`，其他管理员也不能读取或重试；终审发布后的知识原子才写入 `PUBLIC + owner_user_id = null`。
- 公共目标的机器监督按 `PUBLIC + owner=null` 检索相似原子；MySQL 将其编译为 `owner_user_id IS NULL`，Qdrant 将其编译为 owner payload 为空，不能把 null 解释为“不限制 owner”。幂等键同时绑定发起用户、知识库、配置 ID、规范化 Provider、连接端点、模型、temperature、提示词版本、分类和文件哈希，但不包含 API Key，避免共享知识库或可编辑 Provider 配置造成旧批次复用。
- 构建持久化不含密钥的 LLM 运行指纹；排队或重试后端点、模型或 temperature 发生变化时旧批次停止执行。作业重试和进度更新使用状态、重试次数与执行令牌 CAS，租约失效的旧 worker 不得继续调用模型。
- 分类规划、生成、监督和修复调用分别持久化调用与原始响应检查点，再执行结构解析和业务校验；远端结果未知或响应无法确认时只能由用户显式重试授权再次调用，不能把基础设施故障当成内容缺陷自动修复。
- 候选的机器监督与修复只允许在 `review_status = PENDING` 时更新机器字段；人工接受或拒绝通过审核 revision CAS 生效，陈旧 worker 不得覆盖人工决定。
- 外部 JSON 导入包只能形成 `NEEDS_REVIEW` 草稿，并必须包含来源标识和原文证据，不能伪造 `PASS` 绕过终审；只有终审服务内部的受信导入路径可以创建已审核草稿。
- RAG 只消费 `PUBLISHED + PASS + SYNCED` 原子。Qdrant 命中必须由 MySQL 状态回查确认，MySQL fallback 使用相同条件；部分索引失败的批次可以完成发布，但失败原子在重建成功前不可检索。
- 删除私有岗位会先拒绝活动构建，再删除其私有候选、源文档、作业、构建记录和受控存储文件，避免原始文档在岗位生命周期结束后成为孤儿数据。
