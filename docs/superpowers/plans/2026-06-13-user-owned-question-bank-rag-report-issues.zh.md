# 用户自有题库、RAG 与报告重设计 Issue 拆分

状态：按 2026-06-15 受控开放方向修订
日期：2026-06-13，修订：2026-06-15
父级规格：`docs/superpowers/specs/2026-06-13-user-owned-question-bank-rag-report-design.zh.md`
当前领域边界：`CONTEXT.md`

本文档将用户自有题库、RAG 与报告重构拆分为可发布 issue。当前方向从“应用内任意文档上传并自动生成原子”调整为“用户在本机让 Agent 利用题库维护 skill 生成结构化导入包，再通过知识库 / 题库面板仿照原管理员维护流程导入、审查、发布并进入 RAG”。

## 发布说明

- 按依赖顺序发布。
- 创建真实 issue 后，将 `IQB-*` 标识替换为实际 tracker issue ID。
- `HITL` issue 是人工审查闸门，必须由主开发者确认后继续。
- `AFK` issue 应在阻塞项完成后，可由 Agent 在不新增产品决策的前提下独立实现。
- 应用内文件上传、MarkItDown 转换、LLM 自动生成/二审不属于当前 MVP 主线；相关能力移入 followups。

## 修订后的主线

1. 建立公共/私有岗位、知识库、原子和权限边界。
2. 恢复并固定本机题库维护 skill / 导入包契约。
3. 将原管理员题库维护面板的导入、编辑、发布和索引维护流程开放给普通用户维护私有题库。
4. 管理员只额外维护公共 starter 题库；移除开发者统计入口和旧 admin-token 依赖。
5. 面试准备、RAG 检索和报告生成只使用已发布、已同步、严格作用域过滤的原子。

## IQB-01：建立岗位/知识库/原子作用域模型与破坏性迁移

类型：HITL

### 构建内容

为岗位、知识库、知识原子、用户角色、面试轮次、报告和任务引入公共/私有 ownership 模型。
将现有内置题库迁移到三个明确的公共岗位中，保留面向用户的账户数据，并按照已批准的破坏性迁移策略清理旧面试和旧报告数据。

### 验收标准

- [ ] 系统有明确的公共岗位：`Java 后端开发`、`Web 前端开发`、`AI 大模型应用开发`。
- [ ] 每个公共岗位都有一个默认公共知识库。
- [ ] 私有岗位和私有知识库可以用 owner scope 表达。
- [ ] 知识原子支持 public/private scope、owner、position、knowledge base、状态和版本字段。
- [ ] 现有公共题库原子迁移到新的作用域模型中。
- [ ] 旧面试记录、旧报告衍生数据、旧面试绑定的 RAG 日志被清理。
- [ ] 用户账户、用户 LLM Provider 配置、简历画像和反馈被保留。
- [ ] bootstrap 管理员账户可配置为用户名 `nzy333`、邮箱 `1525764737@qq.com`。
- [ ] 迁移行为有文档说明，并可在本地 Docker 测试中重复执行。

### 依赖

无，可立即开始。

## IQB-02：公共/私有资源权限闭环

类型：AFK

### 构建内容

将原管理员题库维护能力按 scope 收口到正常登录用户模型。
管理员可以管理公共岗位、公共知识库和公共题库导入；普通用户可以查看公共内容、复制到自己的工作区，并且只能管理自己的私有内容。
管理员授权本身不是本轮面板开放的核心目标，可继续依赖初始化配置或后续独立管理能力。

### 验收标准

- [ ] 管理员授权使用 JWT 加用户角色，而不是产品流程中的 `APP_ADMIN_TOKEN`。
- [ ] 系统能识别初始化或已有机制赋予的 `ADMIN` 用户，用于公共题库维护。
- [ ] 普通用户不能创建、编辑、发布、重建索引或归档公共资源。
- [ ] 普通用户不能读取或修改其他用户的私有岗位、原子、导入任务或报告。
- [ ] 管理员专属操作在前端隐藏，并且后端授权也会保护。
- [ ] 权限测试覆盖公共、私有、跨用户和管理员专属路径。

## IQB-03：统一异步任务表与本地 TaskExecutor 执行器

类型：AFK

### 构建内容

为导入包解析、草稿落库、发布、重建索引和报告生成创建可恢复的本地任务系统。
任务持久化到数据库，由后端 worker 声明执行，通过轮询 API 暴露状态，并且在失败原因可由用户处理时支持重试。

### 验收标准

- [ ] 任务支持 `PENDING`、`RUNNING`、`FAILED` 和 `COMPLETED` 状态。
- [ ] 任务记录类型、作用域、owner、岗位、知识库、导入批次或面试记录、阶段、进度、脱敏错误消息、是否可重试、重试次数、锁 owner 和锁过期时间。
- [ ] 后端启动时会重新入队 pending 任务和已过期的 running 任务。
- [ ] 失败任务不会自动重试，除非用户主动请求重试。
- [ ] 任务轮询只返回当前用户或管理员可见的任务。
- [ ] 任务生命周期测试覆盖声明、完成、失败、重试和启动恢复。
- [ ] 任务类型不包含 MVP 应用内文档转换和 LLM 原子生成；这些能力进入后续增强。

### 依赖

- IQB-01

## IQB-04：恢复本机题库维护 skill 与导入包契约

类型：HITL

### 构建内容

从仓库历史中恢复本机题库维护 skill 和导入包生成能力，固定 JSON 导入包契约。
该 skill 是用户本机维护题库的生产工具：用户让 Agent 读取准备好的结构化资料并生成标准导入包；它不直接写主应用数据库，不绕过面板权限发布内容。

### 验收标准

- [ ] 恢复并安装 `interview-question-bank` 或等价题库维护 skill。
- [ ] 恢复或重建导入包生成脚本，例如 `scripts/question_bank_import.py`，并明确其输入/输出目录。
- [ ] 导入包 schema 至少包含：package version、position metadata、knowledge base metadata、atoms、tags、difficulty、answer guide、common mistakes、follow-up path、source reference。
- [ ] 导入包中的原子默认是草稿/待审查，不带“已发布”授权语义。
- [ ] skill 输出可被主应用导入 API 校验；校验失败必须能定位到 package、atom index 和字段。
- [ ] 文档说明普通用户维护题库的路径：本机 Agent + skill 生成导入包，通过知识库 / 题库面板手动导入、审查、发布。
- [ ] 不恢复 `APP_ADMIN_TOKEN` 作为正常产品发布路径。

### 依赖

- IQB-01

## IQB-05：题库维护面板导入包校验、批次与草稿落库

类型：AFK

### 构建内容

在知识库 / 题库面板中支持导入结构化 JSON 导入包，校验 schema、权限和业务约束，将合法内容导入为当前用户私有岗位下的草稿原子。
这应复用原管理员题库维护面板的导入批次思路；管理员可以在公共岗位下导入公共草稿，但仍需后续人工发布。

### 验收标准

- [ ] 普通用户只能向自己的私有岗位/知识库导入导入包。
- [ ] 管理员可以向公共岗位/知识库导入导入包。
- [ ] 导入包 schema 校验覆盖必填字段、枚举、长度、数组上限、重复 atom key 和版本兼容。
- [ ] 单次导入默认最多创建 100 个原子草稿，超限时整包拒绝或明确截断策略，不静默丢失。
- [ ] 导入批次记录 package version、scope、owner、position、knowledge base、atom count、status、error summary。
- [ ] 导入成功后所有原子均为草稿或待审查状态，不自动发布、不自动进入 Qdrant。
- [ ] 错误消息脱敏，不暴露 API key、token、绝对私有路径或敏感请求头。
- [ ] 测试覆盖私有导入、公共管理员导入、跨用户拒绝、schema 错误和原子上限。

## IQB-06：开放原题库维护面板为用户工作台 MVP

类型：AFK

### 构建内容

将原开发者/管理员题库维护面板中适合普通用户的能力迁移到知识库 / 题库工作台。
普通用户可以像管理员维护公共题库一样维护自己的私有题库：创建私有岗位、导入导入包、查看导入批次、维护原子草稿、手动创建原子、编辑草稿并提交发布。
页面不保留旧统计入口和运维化入口。

### 验收标准

- [ ] 侧边栏为登录用户暴露 `知识库 / 题库` 入口。
- [ ] 用户可以创建、查看和归档自己的私有岗位。
- [ ] 新私有岗位会自动拥有一个默认知识库。
- [ ] 用户可以在自己的私有岗位中导入 JSON 导入包。
- [ ] 页面展示导入批次状态、草稿数量、待审查数量、已发布数量和索引状态。
- [ ] 用户可以查看、编辑、手动创建和删除未发布草稿原子。
- [ ] 公共岗位可见，但普通用户不可编辑。
- [ ] UI 去掉旧开发者统计入口，不把普通用户引向 admin-token 或脚本发布路径；公共题库维护入口只对管理员开放。
- [ ] 在可行范围内，前端测试覆盖普通用户可见性、公共编辑禁用和导入包错误展示。

## IQB-07：原子人工确认、版本发布与 Qdrant 索引

类型：AFK

### 构建内容

允许用户审查导入包生成的原子草稿、做人工编辑、手动创建原子、发布符合条件的原子，并用严格 ownership payload 将向量同步到 Qdrant。
发布是主应用内授权动作，不能由导入包或 skill 自动触发。

### 验收标准

- [ ] 草稿原子可以由 owner 或管理员发布。
- [ ] 发布前必须通过必填字段、结构、长度、标签和追问路径格式校验。
- [ ] 编辑已发布原子会创建草稿修订版，而不是原地覆盖已发布版本。
- [ ] 发布会替换当前可检索版本，并将旧版本保留为只读历史。
- [ ] 已发布原子会被 embedding 并 upsert 到 Qdrant，payload 包含 scope、owner、岗位、知识库、原子 ID、版本和状态。
- [ ] 向量状态能反映 pending、synced、failed 或 reindex-required。
- [ ] Qdrant 同步失败保留可重试状态，不回滚已经提交的业务事务。
- [ ] 测试覆盖发布资格、版本替换、索引失败和 payload 过滤字段。

### 依赖

- IQB-06

## IQB-08：公共 starter 题库管理员导入与维护流程

类型：AFK

### 构建内容

复用同一套题库维护面板、导入包、草稿审查、发布和重建索引流水线来维护管理员管理的公共岗位。
管理员可以维护公共 starter 内容，普通用户继续以只读方式查看公共内容。

### 验收标准

- [ ] 管理员可以向公共岗位知识库导入 JSON 导入包。
- [ ] 公共导入不依赖 `APP_ADMIN_TOKEN`，只依赖登录用户 `ADMIN` 角色。
- [ ] 管理员可以审查、编辑、发布、归档和重建公共原子索引。
- [ ] 普通用户可以查看公共岗位和公共可用状态，但不能修改公共内容。
- [ ] 公共岗位和公共原子操作由管理员与普通用户权限测试覆盖。
- [ ] 文档明确公共 starter 内容可通过本机题库维护 skill 生成导入包，再由管理员导入发布。

## IQB-09：公共岗位复制为我的岗位

类型：AFK

### 构建内容

允许普通用户将任何公共岗位复制到自己的工作区。
复制后的岗位变为私有岗位，拥有默认私有知识库，并获得已发布公共原子的私有副本和独立私有 Qdrant 索引。

### 验收标准

- [ ] 用户可以将任何 active 公共岗位复制到自己的私有岗位中。
- [ ] 被复制的原子变为私有、归复制用户所有，并保持已发布状态。
- [ ] 复制不会重新执行 LLM 审查或本机 skill。
- [ ] 复制会触发私有 embedding 和带私有 scope payload 的 Qdrant upsert。
- [ ] 公共内容更新不会静默修改用户已有的私有副本。
- [ ] 测试覆盖复制隔离、重复复制命名或冲突行为，以及私有索引 payload。

## IQB-10：面试准备页切换到结构化岗位选择与可用性校验

类型：AFK

### 构建内容

用结构化公共/私有岗位选择替换自由文本或旧版面试岗位选择。
准备流程必须清晰展示岗位是否可用于面试，并在质量前置条件不满足时阻止开始面试。

### 验收标准

- [ ] 面试设置分别列出公共岗位和当前用户的私有岗位。
- [ ] 岗位状态包含 usable、no knowledge、indexing、index failed 和 archived。
- [ ] 已归档岗位不能开始新面试。
- [ ] 没有已发布且已同步原子的私有岗位不能开始面试。
- [ ] Qdrant 或索引不可用状态会阻止开始面试，而不是静默降级检索质量。
- [ ] 前端和后端 guard 都执行同一套开始面试规则。

## IQB-11：面试 RAG 检索切换为严格作用域过滤

类型：AFK

### 构建内容

将面试检索切换到新的 scoped Qdrant payload 模型。
公共面试只能检索所选公共岗位的原子；私有面试只能检索当前用户在所选私有岗位下拥有的原子。

### 验收标准

- [ ] 公共检索始终按 public scope 和所选公共岗位过滤。
- [ ] 私有检索始终按 private scope、当前用户和所选私有岗位过滤。
- [ ] 面试检索绝不执行无作用域的向量查询。
- [ ] 当 Qdrant 不可用或为空时，面试检索不会静默回退到 MySQL。
- [ ] 检索过滤条件由后端服务构造，不依赖可选前端输入。
- [ ] 测试覆盖公共检索、私有检索、跨用户隔离和无回退行为。

### 依赖

- IQB-10

## IQB-12：结构化记录每轮面试对话与检索快照

类型：AFK

### 构建内容

将每一轮面试对话持久化为结构化数据，而不是只依赖原始 chat history。
每轮需要保留问题、用户回答、阶段、检索到的原子引用、prompt context snapshot、检索策略，以及稳定报告生成所需的时间戳。

### 验收标准

- [ ] 新面试记录绑定所选岗位。
- [ ] 每个技术或 HR 轮次保存 AI 问题、用户回答、阶段和轮次索引。
- [ ] 技术轮次保存检索到的原子 ID、版本和来源标签，以及历史报告所需的足够快照数据。
- [ ] 即使原子后续被编辑或归档，报告生成也能使用已保存的轮次数据。
- [ ] 现有面试 UX 在写入结构化轮次数据的同时继续可用。
- [ ] 测试覆盖轮次持久化、阶段分类和原子快照保留。

### 依赖

- IQB-11

## IQB-13：异步报告生成与逐题评分报告

类型：AFK

### 构建内容

将面试结束后的报告生成迁移到统一任务系统。
报告应展示生成中、已完成或失败状态；已完成报告应包含逐题评分、参考答案或参考方向、改进建议，以及可见的答案来源标签。

### 验收标准

- [ ] 结束面试会创建 `GENERATE_REPORT` 任务，而不是阻塞等待完整报告生成。
- [ ] UI 可以展示报告生成中、已完成、失败和重试状态。
- [ ] 报告生成失败时保留面试数据，并允许重试。
- [ ] 技术题和 HR 题都获得 0-10 的综合逐题评分。
- [ ] 开场和收尾轮次不作为单独报告项评分。
- [ ] 报告项包含问题、用户回答、得分、参考答案或方向、改进建议和来源标签。
- [ ] 来源标签区分知识库参考、AI 生成技术参考和 HR 指导。
- [ ] 测试覆盖报告任务生命周期、分数解析、来源标签和历史快照稳定性。

### 依赖

- IQB-03
- IQB-12
